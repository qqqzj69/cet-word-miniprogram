## 一、项目定位

| 项 | 内容 |
|---|---|
| 项目名称 | **贝贝四六级** · 英语四六级背单词小程序 |
| 本质 | 微信小程序（原生框架，无第三方 UI 依赖，无构建步骤） |
| 定位 | **自己备考用的日常工具**：真的能用来背四六级单词，同时按工程化标准编写，保证可长期维护、可交接 |
| 目标平台 | 微信小程序（基础库 2.20+，兼容 iOS / Android） |
| AppID | 暂缺，使用**测试号**开发；结构与正式版一致，后续填入 AppID 即可发布 |

### 1.1 目标用户与场景

- **主用户**：备考大学英语四级 / 六级的在校生（本人为首要用户）
- **其他读者**：可能阅读代码的同学 / 开发者
- **典型场景**：
  1. 通勤 / 课间碎片时间，打开小程序背 20 个单词
  2. 睡前查看今日学习统计，完成打卡
  3. 复习昨日错词

### 1.2 成功标准

- 冷启动 < 1.5s；主包体积 < 1.5MB
- 断网可完整使用（词库与题库全部内置）
- 杀进程 / 关机后学习进度、错词本、打卡记录**不丢失**
- 任何人可在 5 分钟内 clone 仓库并用微信开发者工具跑起来
- 微信审核可一次性通过（无外链、无诱导、无未声明权限）

## 二、核心目标（三条，不可动摇）

1. **可独立运行**：零后端、零域名、零备案。全部数据内置 + 本地持久化，任何人 clone 即可运行。
2. **数据不丢**：采用微信本地存储持久化。仅在用户**主动注销 / 清除数据**时才清空。
3. **精简而完整**：只做「背单词」与「统计打卡」两条主线，砍掉听力、社交、支付等非核心功能。功能少但每个都稳定可用。

## 三、功能规划

### 3.1 功能清单（MVP）

| 编号 | 模块 | 功能点 | 优先级 |
|---|---|---|---|
| F1 | 学习 | 选择词库（四级 / 六级） | P0 |
| F2 | 学习 | 卡片式背单词：正面单词，点击翻转看释义 | P0 |
| F3 | 学习 | 认识 / 模糊 / 不认识 三档自评，驱动记忆算法 | P0 |
| F4 | 学习 | 每日学习量设定（默认 20 词） | P0 |
| F5 | 学习 | 学习进度条 + 今日完成态 | P0 |
| F6 | 复习 | 错词本：自动收集「不认识 / 模糊」的词 | P0 |
| F7 | 复习 | 错词专项复习模式 | P1 |
| F8 | 统计 | 今日学习词数、正确率、连续打卡天数 | P0 |
| F9 | 统计 | 近 7 日学习量柱状图（纯 CSS 实现，无图表库） | P1 |
| F10 | 统计 | 累计学习词数、掌握词数、总打卡天数 | P1 |
| F11 | 打卡 | 每日打卡，连续天数计算与断签处理 | P0 |
| F12 | 设置 | 切换四级 / 六级、每日目标设定 | P0 |
| F13 | 设置 | 清空学习数据（二次确认）、关于页 | P1 |

### 3.2 明确不做（避免过度设计）

- ❌ 听力训练（用户明确排除）
- ❌ 真题阅读 / 长篇文章
- ❌ 用户系统、云同步、后端服务
- ❌ 支付、广告、分享裂变
- ❌ 单词发音音频（离线包体积代价过大，后续可加）

### 3.3 记忆算法

采用**简化艾宾浩斯（SM-0 变体）**，对每个单词维护 `stage`（0-6）与 `nextReviewAt`：

| 自评 | stage 变化 | 下次复习间隔 |
|---|---|---|
| 不认识 | 归 0 | 立即（10 分钟后） |
| 模糊 | -1（最低 0） | 1 天 |
| 认识 | +1（最高 6） | 1 / 2 / 4 / 7 / 15 / 30 天 |

- 每日从「已到期 + 未学完」的词中取每日目标数量组成学习队列
- 队列当日完成即算一次有效学习，可打卡

## 四、技术架构

### 4.1 技术选型

| 维度 | 选择 | 理由 |
|---|---|---|
| 框架 | **原生小程序**（WXML / WXSS / JS） | 无构建步骤，clone 即跑；原生性能最好；不依赖第三方 UI 库，长期维护成本低 |
| UI 组件 | **全部自研 CSS** | 不引入 TDesign / WeUI 等 npm 依赖，避免 node_modules 构建；完全可控的视觉风格 |
| 状态 | `app.globalData` + 自定义 store 模块 | 轻量、无依赖 |
| 存储 | `wx.setStorageSync` 同步 API | 可靠性高于异步，写入即落盘；数据量小（< 100KB），同步无性能问题 |
| 数据 | 内置 JS 模块（`data/*.js`） | 无网络请求，无域名白名单，离线可用 |

### 4.3 存储设计（持久化）

所有数据落在 `wx.setStorageSync`，**单 key 根对象** `cet_word_db_v1`，结构：

```js
{
  version: 1,
  currentLevel: 'cet4',          // 'cet4' | 'cet6'
  dailyGoal: 20,
  words: {                        // 每词学习状态（仅存学过的，未学不占空间）
    "ability": { s: 3, n: 1730000000000, w: 0 },  // stage, nextReviewAt, wrongCount
    ...
  },
  daily: {                        // 按 'YYYY-MM-DD' 归档
    "2026-09-19": { learned: 20, right: 14, vague: 4, wrong: 2 }
  },
  checkins: ["2026-09-17", "2026-09-18"],  // 已打卡日期
  createdAt: 1730000000000
}
```

**持久化保障**：
- 每次学习动作后**立即**同步写入（不等页面卸载）
- `app.onHide` / `onUnload` 兜底保存
- 读取时做 schema 校验，损坏则回退到安全默认值而非崩溃
- **只有**用户在「我的 → 清除学习数据」中二次确认后才清空

## 五、UI 设计方向

### 5.1 GitHub 设计参考（已调研）

| 仓库 | Stars | 借鉴点 |
|---|---|---|
| `Tencent/tdesign-miniprogram` | 高 | 企业级间距 / 层级规范、组件状态完整度 |
| `ant-design/ant-design-mini` | 551 | 表单与反馈类组件的克制表达 |
| `openages/light-design` | 16 | 轻盈留白、大圆角、柔和阴影 |
| `getaskclaw/aqua-weapp-ui` | 6 | 液态玻璃（Liquid Glass）浅底质感、零依赖实现思路 |
| `weui` (官方) | — | 微信小程序控件的安全区与原生一致性 |

### 5.2 视觉语言：「晨读纸感」Light Academic

- **底色**：暖白纸感 `#F7F5F2`（非纯白，降低刺眼感），卡片纯白 + 极淡描边
- **主色**：靛青 `#2F5FE0` → 青绿 `#16B8A8` 渐变，用于进度、主按钮
- **辅助色**：琥珀 `#F5A623`（打卡 / 连续天数）、珊瑚红 `#FF6B5B`（错词）
- **文字**：主 `#1A1D24` / 次 `#6B7280` / 弱 `#9CA3AF`
- **圆角**：卡片 20rpx，按钮 16rpx，标签 999rpx
- **阴影**：极浅双层阴影，避免脏灰
- **字体**：系统字体栈，数字使用等宽感排版增强统计感
- **深色模式**：预留 CSS 变量，通过 `wx.getSystemInfoSync().theme` 跟随系统

### 5.3 交互动效

| 场景 | 动效 |
|---|---|
| 单词卡片翻转 | `rotateY` 3D 翻转 + 背面内容延迟淡入（0.45s，cubic-bezier 缓动） |
| 自评按钮 | 按下缩放 0.94 + 轻触觉反馈 `wx.vibrateShort` |
| 切换下一个词 | 新卡片从右侧 24rpx 位移淡入，旧卡向左滑出 |
| 进度环 | `stroke-dashoffset` 动画，0.6s 补间 |
| 统计数值 | 数字滚动计数动画 |
| 打卡成功 | 印章缩放弹跳 + 微光扩散 |
| 列表入场 | 错峰（stagger）上浮淡入 |

> 全部使用 CSS `transition` / `animation` + `wx.createAnimation` 实现，不引入动画库。
